# Current ABI5 backend and CPU consumer

The current backend uses the existing closed compiler and H08 consumer.
`closedbuild.ReadArtifact` authenticates the backend-only producer, complete
historical Go snapshots, actual native dependencies, compiler and link evidence,
all ABI exports, and selected runtime files. H08 `AuthenticateBackend` uses this
reader. Its CPU13 fixture view selects a new backend while preserving the eight
retained fixture files and genuine HAC conv0 weight witness. Its runtime launch
uses the shared SUP audited-load guard. No legacy `status=built` document or
ABI4 reader is needed for this connection.

The current tensor tests have external D03 and D04 adapter tests. The H08 CGo
builder now records their exact files and imports, pins their source, and adds
their entries to the expected Go1.27 test main. It verifies actual external files
and imports alongside the fixed add-only TestMain overlay. The source test main
cannot replace that overlay. The existing eleven genuine CPU13 tests and two
separately admitted fake tests remain the selected qualification set. Additional
external tests compile into the current test binary. They do not run implicitly.

The native source declares 46 mandatory loader exports. Six are the guide
program and frame, beam program and numbers, post numbers, and SUP operation.
ABI 5 and explicit SUP geometry, including short geometry 3, remain required.
The source-short wire controls are separately queued. Their host result cannot
qualify native SUP arithmetic or native decoder numerics.

The static request and execution wrapper are under `artifacts/abi5-backend-001`.
Their host phase runs focused source-builder and artifact-reader controls,
rebuilds the two sealed closed controllers, and prepares a fresh backend-only
plan. Its compiler phase needs a new exact grant and the resulting plan digest.
Each compiler child retains its 180-second deadline. Both phases use two CPUs,
3 GiB memory, zero swap, and at most 64 tasks. Commands that lock internally
receive no outer stock-lock hold. Every output and cache is new.

A backend compiler result remains unexecuted. A later host-only backend proof
must call the H08 reader over independently pinned build, plan, producer, and
output anchors. Fresh H08 command and CPU13 CGo builds then need the existing
finite query and compiler controls before an audited runtime grant. Runtime
loading, fixture tests, device creation, PTX JIT, GPU work, and model execution
are held. Historical ABI4 readers and receipts remain unchanged.

Per-profile model weight and cache duplication is an independent integration
problem. This backend unit does not resolve persistent cache ownership, full
SUP plus short-profile capacity, complete caller readiness, or performance.
Later Go cache changes require current consumer custody to be rebuilt. Native
C++ evidence can remain reusable only while all declared native inputs match.
