# D01 invocation proof and watcher budget

The numeric capture controller uses one private historical-lineage proof context
per invocation. Exact anchor path, SHA256, historical validation mode and epoch
identify its entry. Only a successful complete walk is cached. Borrowers receive
decoded copies of a private byte snapshot; no cache survives the invocation.
Standalone readers continue to authenticate freshly.

`Capture` acquires the existing host lock read-only and nonblocking before
creating its context or reading proof metadata. Historical custody cannot satisfy
current source, selected tool, executable, provider, driver, environment, mapping,
phase, image or numeric identity admission.

The external-call boundary invalidates the pre-child entry, performs a complete
post-child historical walk, and checks the current runtime on both success and
failure. Joined errors preserve execution, historical authentication and runtime
failures. Success then retains its existing output, identity and final runtime
checks. Failed captures remain failed receipts. `CheckCapture` owns an independent
context and completes its own final historical authentication before qualification.
Metadata is hashed and decoded from the same bounded buffer; large file pin
checks remain streaming. Size or timestamps never authorize reuse.

The handler and numerical outer unit still require separate sealing and review.
These budgets are limits, not measured proof that genuine numerical capture fits.
Do not increase them to accommodate repeated historical walks.

Host verification uses the actual serialized Go `WatchPlan` and unchanged pinned
Python watcher. Popen sentinels prove controller900/561 and native181 reject before
creation, while numeric540/native180 and legacy240 reach controller creation.
Additional fake peers drive actual watcher/OwnedGroup timeout and cleanup paths,
including retained cleanup failure and exclusive-output failure. They launch no
controller or native producer and send no real process signals.

Proof controls cover one walk per epoch, separate invocations, exact keys,
immutable returned records, uncached failures, authenticated metadata and
same-size/restored-time mutations of metadata, image, consumer snapshot,
alias binding and membership on successful and failed children. Current source
and executable checks remain separate. Existing identity/provider/environment,
source membership, supervisor ownership and output controls remain required.
